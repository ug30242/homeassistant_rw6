# 설치 및 초기 설정

## 설치

1. [GitHub Releases](https://github.com/ug30242/homeassistant_rw6/releases)에서 같은 버전의 APK와 RPK를 다운로드합니다. `SHA256SUMS`와 비교하면 파일 손상을 확인할 수 있습니다.
2. Android에서 APK를 열어 해당 파일 관리 앱의 알 수 없는 앱 설치 권한을 허용합니다. 최소 Android 8.0(API 26)입니다.
3. Notify for Xiaomi에서 연결한 Redmi Watch 6에 로컬 RPK 파일 설치 기능으로 `.rpk`를 전송합니다. Notify 버전에 따라 메뉴 이름이 다를 수 있습니다. 설치 후 워치 앱 목록에서 `HA Control`을 확인합니다.
4. Mi Fitness 중국판 운동건강(`com.mi.health`) 또는 지원되는 Mi Fitness(`com.xiaomi.wearable`)의 기존 워치 연결을 유지합니다. Notify만으로는 XMS 설정 동기화가 되지 않습니다. 필요하면 Notify 설치 후 Mi Fitness를 다시 열어 연결을 복구합니다.
5. 기존 TOTP 앱은 삭제할 필요가 없습니다. HA 앱은 별도 패키지·아이콘·저장소·서명을 사용합니다.

APK와 RPK 중 하나만 개발용 빌드로 교체하면 서명이 달라 XMS가 거부할 수 있습니다. 같은 릴리즈의 두 파일을 사용하세요. 앱 업데이트는 기존 HA 서명을 유지해야 합니다.

## Home Assistant 토큰과 서버

1. Home Assistant의 사용자 프로필 → 보안 → 장기 액세스 토큰(Long-Lived Access Tokens)에서 워치 전용 토큰을 생성합니다. 가능하면 필요한 엔티티 접근 권한을 가진 전용 일반 사용자를 사용하세요. 토큰은 해당 사용자의 권한을 따릅니다.
2. Android의 `서버` 탭에서 `https://ha.example.com` 또는 `https://ha.example.com/하위경로`처럼 최종 기본 주소를 입력합니다. `/api/`를 뒤에 붙이지 마세요. 사용자명·비밀번호·쿼리·fragment를 URL에 포함할 수 없습니다.
3. 토큰 입력 → `암호화 저장` → `저장 후 서버 연결 테스트`를 실행합니다. 토큰 입력칸을 비우면 기존 토큰을 유지합니다. 서버 주소를 바꿀 때는 해당 서버의 새 토큰을 입력하세요.
4. 정상 TLS 인증서를 사용해야 합니다. 자체 서명 인증서 검증을 무시하는 기능은 없습니다. 신뢰하는 로컬망의 `http://192.168.x.x:8123`는 `HTTP 허용`을 직접 선택한 경우만 가능합니다. 이 경우 토큰이 평문으로 전송됩니다.
5. Android에서 연결된다고 워치에서 연결되는 것은 아닙니다. 워치의 네트워크 경로·DNS·인증서 신뢰는 별도로 테스트해야 합니다. 재설정·분실 시 Home Assistant에서 토큰을 폐기하세요.

## 엔티티 선택·정렬

1. `엔티티` 탭 → `엔티티 목록 자동 조회`로 `/api/states` 목록을 가져옵니다. v0.1.1부터 큰 응답을 스트리밍으로 읽고 이름·ID만 보관하므로 2,000개 이상의 목록도 기존 2 MiB 제한 없이 조회할 수 있습니다. Home Assistant REST 목록 API에는 도메인별 페이지 요청이 없어 네트워크에서는 전체 응답을 읽되, 무거운 상태·속성 데이터는 버립니다. 응답은 gzip을 지원하며 압축 해제 후 128 MiB / 50,000개로 제한합니다.
2. 조회 후 조명·스위치·팬·커튼·센서·장면·스크립트의 도메인별 조회 개수와 선택 개수가 함께 표시됩니다. 선택 개수는 검색·페이지와 관계없는 전체 선택 기준입니다. 처음에는 모두 접혀 있으며 원하는 도메인을 눌러 한 번에 하나씩 펼칩니다. 한 페이지에 50개씩 보이고 `이전`/`다음`으로 끝까지 탐색할 수 있습니다. 이름/entity_id 검색은 페이지 밖의 전체 지원 엔티티에도 적용되며 검색 결과 개수를 도메인별로 표시합니다. 워치용 선택은 최대 80개입니다.
3. `선택목록` 탭 또는 `선택목록 검토`를 누릅니다. 서버 재조회 없이 전체 선택 항목을 검토하고 이름·ID·그룹 검색, 도메인 필터, 즐겨찾기만 보기로 좁힐 수 있습니다. 각 카드의 `워치 이름`은 실제 ASCII 대체 표시를 미리 보여줍니다. `편집`에서 이름(80자), 아이콘(32자), 공간/그룹(40자), 즐겨찾기를 지정합니다. 아이콘은 `light`, `switch`, `fan`, `cover`, `sensor`, `scene`, `script` 중 선택하거나 `mdi:lightbulb`, `mdi:toggle-switch`, `mdi:fan`, `mdi:curtains`, `mdi:blinds`, `mdi:thermometer`, `mdi:palette`, `mdi:script` 별칭을 입력합니다. 7종 내장 PNG를 사용하므로 아이콘 글꼴이 필요 없습니다. 등록되지 않은 아이콘은 기기 종류의 이미지로 대체하며, 워치 카드에는 실제 도메인 종류를 별도로 표시합니다.
4. `선택목록` 탭에서 `즐겨찾기 · 워치 Favorites`를 바로 켜고 끌 수 있습니다. `↑`/`↓`로 전체 선택 목록의 순서를 바꿉니다 (검색/필터를 적용해도 전체 순서 기준). 워치는 즐겨찾기를 먼저, 같은 우선순위에서는 지정 순서대로 표시합니다.
5. 체크 해제 또는 `삭제`를 누른 뒤 동기화하면 워치에서도 삭제됩니다. 선택 목록이 비어 있는 설정도 동기화할 수 있습니다.

## XMS 연결과 동기화

1. 워치에서 `HA Control` → `Sync`를 열고 화면을 유지합니다.
2. Android의 `워치` 탭 → `워치 연결 / 다시 연결`을 누릅니다. 여러 워치가 있으면 선택합니다.
3. Mi Fitness가 요청하는 동반 앱 기기 통신 권한을 허용합니다. Android 일반 권한 팝업과 다른 XMS 권한입니다.
4. `전체 설정 워치 동기화` → 워치에 토큰을 저장한다는 안내를 확인하고 진행합니다.
5. `워치 저장 응답 확인`이 표시될 때까지 두 앱의 동기화 화면을 유지합니다. 단순 연결됨·전송됨은 저장 완료가 아닙니다. 워치가 준비 응답을 주기 전에는 토큰을 전송하지 않습니다.
6. 완료 후 Android 관리앱은 종료할 수 있습니다. 워치는 저장한 설정으로 직접 통신하며 Mi Fitness 네트워크 경로는 필요할 수 있습니다.

동기화 도중 앱을 닫으면 취소됩니다. 전송은 메모리에 모은 다음 전체 검증·저장을 수행하므로 부분 수신은 기존 설정을 덮어쓰지 않습니다. 저장은 완료됐으나 ACK만 유실될 수도 있으므로 시간 초과 시 워치 목록도 확인하세요. 동일 내용·버전 재전송은 중복 저장하지 않습니다.

## 워치 조작

- 첫 필터는 `Favorites`입니다. 즐겨찾기가 없으면 해당 버튼을 눌러 `All`, 이후 공간별 목록으로 순환합니다.
- 메인 목록은 저장된 카드만 표시하며 Home Assistant에 상태 조회·제어 요청을 보내지 않습니다. 큰 아이콘, 실제 종류(Light/Switch/Fan/Cover/Sensor/Scene/Script), 두 줄 이름으로 항목을 구분합니다. 카드 전체를 터치하면 상세화면으로 이동하고 그때 상태를 조회합니다.
- 상세화면의 ON/OFF·Refresh state와 도메인별 제어를 사용합니다. Android 서버 탭에서 정한 30/60/120초 자동 갱신도 활성 상세화면에만 적용하며, 목록으로 돌아가면 중지합니다.
- 커튼 상세의 열기·닫기·정지·위치와 조명 밝기는 Home Assistant가 보고한 지원 기능에 따라 표시합니다.
- 센서는 표시만 합니다. `scene`/`script`는 `Run`으로 실행하고 실행 시각 변경을 다시 조회합니다.
- `Sent; state change unconfirmed`는 요청은 수락됐으나 기대 상태·실행 증거를 아직 확인하지 못했다는 뜻입니다. 커튼 이동 등 오래 걸리는 작업은 잠시 후 새로고침하세요.
- `STALE`은 과거 상태입니다. 인증·네트워크 오류가 난 상태로 제어 버튼을 계속 표시하지 않습니다. `unavailable`/`unknown`도 제어를 비활성화합니다.
- 한글 엔티티 이름은 `light.living_room` → `Living room`처럼 읽기 쉬운 ASCII 이름으로 대체합니다. 목록에서는 표시할 수 없는 한글 그룹 설명을 생략하고 필터를 Group 1/2 순서로 구분합니다. 한글 상태는 상세화면에서 `See Home Assistant`로 표시합니다. Android에서 ASCII 이름·그룹을 지정하면 더 알아보기 쉽습니다.

## 워치 네트워크 테스트

1. `Info` → `Test GET /api/ + entity`: 워치의 `@system.fetch`로 Bearer 인증을 넣어 API 확인과 첫 선택 엔티티의 상태 조회를 수행합니다.
2. `Test POST: update entity`: `/api/services/homeassistant/update_entity`에 첫 선택 엔티티를 보내 새로고침을 요청한 뒤 상태를 조회합니다. 일반적인 켜기·닫기 명령으로 테스트하지 않습니다. 해당 서비스 권한이 필요하며 특정 통합의 업데이트 동작은 Home Assistant 설정을 따릅니다.
3. Android 설정 관리자 앱을 시스템 설정에서 **강제 종료**하고 위 두 테스트와 실제 기기 제어를 반복합니다. Mi Fitness는 연결을 유지합니다.
4. [실기기 검증표](validation.ko.md)에 펌웨어·Mi Fitness 버전·결과를 기록합니다. 오류 화면이나 기록에 토큰을 넣지 마세요.

## 인증정보 삭제

- Android `로컬 토큰 삭제`는 로컬 토큰과 엔티티를 제거하고 워치 삭제용 설정을 준비합니다. 이후 `워치` 탭에서 동기화해야 워치의 기존 토큰도 지웁니다.
- 워치 단독으로는 `Info` → `Erase watch credentials` → 확인을 누릅니다. 두 설정 슬롯을 비우고 읽기 확인을 합니다.
- 일반 플래시 저장소에서의 삭제는 물리적 보안 삭제를 보장하지 않습니다. 토큰 폐기가 필요하면 Home Assistant 프로필에서 해당 토큰을 삭제하세요.
- Android 암호화 저장소 오류가 나면 `워치` 탭의 `Android 저장소 초기화`로 복구할 수 있습니다. 이 작업도 워치 데이터는 자동으로 지우지 않습니다.

## 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| Mi Fitness 서비스 없음 | 중국판 운동건강/지원 Mi Fitness 설치, 워치 연결, 앱 다시 실행 |
| 서명 불일치 / XMS -6 | 같은 릴리즈 APK와 RPK 설치. 개발용·릴리즈 혼용 금지 |
| 권한 오류 / -7 | Mi Fitness 동반 앱 기기 통신 권한 허용 후 다시 연결 |
| 워치 앱 없음 / -5·-8 | HA RPK 설치. TOTP RPK로는 연결할 수 없음 |
| Reply failed 1006 / 준비 응답 없음 | Mi Fitness 연결, 서명·패키지·권한 확인, HA 두 앱 업데이트, 워치 Sync 화면 열기, 다시 연결. 수신 카운트만으로 왕복 성공으로 판단하지 않음 |
| 저장 응답 시간 초과 | 워치 저장 상태 확인 후 재시도. 중단·중복 전송은 전체 검증 후 처리 |
| 더 최신 설정 있음 | Android 설정을 다시 저장해 버전 증가. 시계가 과거로 바뀌었다면 시간 교정. 필요 시 워치 설정 삭제 후 재동기화 |
| 401/403 | 토큰 유효성, 사용자 권한 확인. 새 토큰 저장 후 재동기화 |
| 404 | 기본 URL 하위경로, 삭제된 entity_id, 서비스 지원 여부 확인 |
| 429/5xx | 수동 갱신으로 전환하고 서버 복구 후 재시도 |
| TLS/DNS/timeout | 워치 네트워크 경로와 Mi Fitness, 서버 DNS·공인 인증서, 로컬망 도달 가능 여부 확인 |
| unavailable/unknown | HA 통합/기기 상태 확인. 기기가 복구되면 새로고침 |
| 제어 후 unconfirmed | 실제 상태를 다시 조회. 장시간 커튼 동작·비동기 스크립트·서버/워치 시간 차이 가능 |

fetch 직접 통신이 펌웨어에서 막힌 것으로 확인되면 펌웨어·응답 코드·GET/POST 별 결과를 기록하세요. 현 앱은 Android 상주 중계로 전환하지 않습니다. Mi Fitness 버전·권한·공인 HTTPS 서버 경로를 점검하고, 펌웨어가 지원하지 않으면 해당 환경에서의 직접 제어는 지원 불가로 판단해야 합니다.
