# Redmi Watch 6 Home Assistant 제어 앱 개발

## 1. 개발 목표

중국 내수판 Redmi Watch 6에서 Home Assistant 기기를 조회하고 제어할 수 있는 앱을 개발한다.

기존 `ug30242/totp_rw6` 프로젝트의 Android ↔ Redmi Watch 6 동기화 구조를 참고하되, 별도 프로젝트로 개발한다.

**핵심 아키텍처**

- Android 앱(APK): Home Assistant 서버 설정, 인증 토큰 관리, 엔티티 선택 및 정렬, 워치 설정 동기화만 담당
- Redmi Watch 6 앱(RPK): 동기화된 설정을 로컬에 저장하고, Home Assistant REST API에 직접 연결하여 상태 조회 및 기기 제어
- Mi Fitness: 기존 워치 연결 유지 및 XMS 설정 동기화에 사용
- 별도 서버, 클라우드 중계, Android 백그라운드 상주 서비스는 개발하지 않음

**가장 중요한 조건:** Android 관리앱을 완전히 종료하더라도 Redmi Watch 6에서 Home Assistant 상태 조회와 기기 제어가 가능해야 한다. 단, Mi Fitness가 제공하는 네트워크 경로는 사용할 수 있다.

## 2. 기존 TOTP 프로젝트 분석 및 재사용

참고 저장소: https://github.com/ug30242/totp_rw6

먼저 해당 저장소의 실제 구현을 분석한다.

주요 참고 파일:
- `android/app/src/main/java/com/vela/rw6totp/XmsClient.java`
- `android/app/src/main/java/com/vela/rw6totp/SyncSession.java`
- `src/common/phone-channel.js`
- `src/common/phone-wire.js`
- `src/pages/receive/index.ux`
- `docs/xms-reply-1006.md`
- Android Keystore 기반 저장소 및 APK/RPK 빌드·서명 관련 코드

기존 프로젝트의 Xiaomi XMS 서비스 연동, AIDL/Binder, `@system.interconnect`, 송수신 확인, 타임아웃, 재시도, 메시지 파싱 등 검증된 구조를 최대한 재사용한다.

특히 기존 프로젝트에서 수정한 XMS 서비스 연결 등록 누락 및 응답 오류 1006 관련 사항을 반영한다.

단, TOTP 프로젝트에서 실기기 양방향 통신이 최종 검증되었는지는 별도로 확인해야 한다. 코드상 테스트 통과와 실제 Mi Fitness/워치 통신 성공을 구분한다.

기존 TOTP 프로젝트의 코드, 패키지명, 앱 식별자, 저장 데이터와 서명을 임의로 변경하거나 손상시키지 않는다.

새로운 Android 앱과 RPK는 별도 패키지로 개발하며, 해당 APK와 RPK의 XMS 통신에 필요한 패키지 식별자 및 서명 일치 조건을 반영한다.

## 3. 통신 아키텍처

### A. 설정 동기화

Android 앱 → Mi Fitness XMS → Redmi Watch 6

Android에서 설정한 다음 정보를 워치에 전송한다.

- Home Assistant 서버 URL
- 인증 토큰
- 선택한 엔티티 ID
- 사용자 지정 표시 이름
- 아이콘 및 기기 유형
- 정렬 순서 및 그룹
- 기타 워치 표시 설정

워치는 수신한 설정을 로컬 저장소에 보관한다.

설정 동기화는 사용자가 Android 앱에서 실행하며, 완료 후 Android 앱이 실행되어 있을 필요가 없어야 한다.

기존 TOTP의 요청 ID 기반 ACK, 저장 성공 확인, 재전송 방지 구조를 활용한다. XMS 메시지 크기 제한을 고려해 데이터 분할 전송과 완료 확인을 구현한다.

전체 설정을 버전 관리하고 중복·부분 수신·통신 중단 시 기존 정상 설정이 훼손되지 않도록 한다. Android에서 엔티티를 삭제하면 다음 동기화에서 워치에도 반영한다.

### B. 워치의 직접 통신

Redmi Watch 6 → Home Assistant REST API

Xiaomi Vela의 `@system.fetch`를 사용한다.

주요 API:
- `GET /api/`: 서버 연결 확인
- `GET /api/states/{entity_id}`: 상태 조회
- `POST /api/services/{domain}/{service}`: 기기 제어

Bearer Token 인증을 사용한다.

워치에서 직접 API 요청을 처리하며 Android 관리앱을 호출하지 않는다.

HTTP 요청 결과를 확인하고 실제 엔티티 상태를 다시 조회한다. 명령을 보냈다는 이유만으로 제어 성공으로 표시하지 않는다.

네트워크 통신은 필요한 시점에 수행하고, 배터리 소모를 최소화한다.

## 4. 개발 우선순위: 워치 네트워크 검증

본격적인 기능 개발에 앞서 Redmi Watch 6의 네트워크 요청 기능을 검토하고 테스트 기능을 구현한다.

확인 사항:
1. 중국 내수판 Redmi Watch 6에서 `@system.fetch` 사용 가능 여부
2. Mi Fitness 연결 상태에서 외부 HTTPS 통신 가능 여부
3. Home Assistant 서버로 직접 GET/POST 요청 가능 여부
4. Authorization 헤더 전달 가능 여부
5. 요청 타임아웃, 응답 처리, 통신 실패 시 동작

우선 워치 앱에 네트워크 테스트 기능을 구현한다.

실제 기기 검증이 필요한 항목은 검증되지 않았다고 명확히 구분하되, 실기기 부재를 이유로 개발을 중단하지 않는다. 가능한 코드 구현과 자동 테스트를 진행한다.

직접 통신이 불가능한 것으로 확인되더라도 Android 백그라운드 중계 방식으로 임의 변경하지 않는다. 원인과 대안을 정리하고 현재 아키텍처에서 구현 가능한 기능까지 완성한다.

## 5. Android 관리앱 기능

사용자가 워치에서 설정할 필요가 없도록 모든 관리 기능을 Android에 구현한다.

### 서버 관리
- Home Assistant URL 입력 및 수정
- Long-Lived Access Token 입력·수정·삭제
- 서버 연결 테스트
- 인증 오류·네트워크 오류 구분
- 연결된 서버 정보 표시
- HTTPS 인증서 정상 검증

### 엔티티 관리
- Home Assistant에서 엔티티 목록 자동 조회
- 도메인별 분류 및 검색
- 표시할 엔티티 다중 선택
- 표시 이름 및 아이콘 변경
- 즐겨찾기 지정
- 드래그 방식 등으로 정렬 순서 변경
- 화면 그룹 지정
- 엔티티 추가·삭제
- 저장한 설정 워치 동기화

초기 지원 대상으로 조명(light), 스위치(switch), 팬(fan), 커튼(cover), 센서(sensor), 장면(scene), 스크립트(script)를 포함한다.

지원 가능한 각 도메인에 대해 상태와 제어 명령을 정확하게 매핑한다. 센서처럼 읽기 전용인 엔티티는 제어 버튼을 표시하지 않는다.

향후 climate, number, select, input_boolean 등으로 확장할 수 있도록 구성한다.

### 워치 연결
- 연결된 워치 확인
- 동기화 실행
- 동기화 성공·실패·진행 상태 표시
- 워치 저장 확인
- 연결 실패 후 재시도
- 최초 연결 권한 안내

### 보안
- 인증 토큰은 Android Keystore 기반 암호화 저장
- GitHub 소스, 로그, 오류 메시지에 토큰 노출 금지
- 워치에 토큰을 전송할 때 보안상 주의사항 안내
- 워치 일반 저장소가 안전한 암호화 저장소라고 가정하지 않음
- 사용하지 않는 자격 증명 삭제 지원

UI는 한국어를 기본으로 하며, 깔끔하고 현대적인 디자인을 적용한다.

## 6. Redmi Watch 6 앱 기능

화면 해상도 432×514를 기준으로 터치 조작에 최적화한다.

### 메인 화면
- 즐겨찾기 엔티티 우선 표시
- 엔티티 이름, 아이콘, 현재 상태 표시
- ON/OFF 버튼
- 화면 진입 시 상태 조회
- 새로고침 기능
- 연결 상태 및 마지막 갱신 시간 표시

### 엔티티 제어
- 조명·스위치·팬 켜기/끄기
- 커튼 열기·닫기·정지
- 지원 시 조명 밝기와 커튼 위치 조절
- 센서 상태 확인
- 장면 및 스크립트 실행
- 명령 결과와 오류 표시

### 화면 구성
- 즐겨찾기
- 공간/그룹별 목록
- 엔티티 상세 제어
- 연결 상태 및 간단 설정

목록 및 세부 제어 화면은 작은 화면에서 오작동을 방지하도록 충분한 터치 영역을 확보한다.

기존 TOTP에서 발생했던 중국 내수판 한글 글꼴 깨짐 문제를 고려한다. 워치 UI 기본 문구는 ASCII 영어를 우선 사용하고, 사용자 지정 엔티티 이름에 한글이 포함되면 지원 여부에 따라 대체 표시를 제공한다.

### 상태 갱신
- 앱 실행 및 화면 재진입 시 조회
- 명령 실행 후 실제 상태 재조회
- 수동 새로고침
- 앱 활성 상태에서만 필요에 따라 주기적 조회
- 연결 실패 시 마지막 상태와 오류를 명확히 구분

불필요한 상시 폴링을 방지한다.

- HTTP 오류 코드별 처리
- 토큰 만료·변경·삭제 대응
- Home Assistant 서버 오프라인 상태
- 워치와 Android 설정 버전 불일치
- 엔티티가 삭제되거나 unavailable인 경우
- 중복 명령 및 빠른 연속 터치 방지

- 네트워크 지연 시 비동기 UI 처리

TOTP 프로젝트에서 이미 해결한 문제를 재발시키지 않도록 관련 회귀 테스트를 참고한다.

## 8. 빌드 및 배포

최종적으로 다음 설치 파일을 생성할 수 있어야 한다.

- Android 관리앱 `.apk`
- Redmi Watch 6 앱 `.rpk`

기존 TOTP 앱과 독립적으로 설치되도록 구성한다.

GitHub Actions를 통한 APK/RPK 자동 빌드 및 Release 배포 구조도 마련한다. 서명 키는 저장소에 포함하지 않고 GitHub Secrets 등으로 관리한다.

개발 문서에는 다음을 포함한다.
- Android APK 설치 방법
- Notify for Xiaomi를 통한 RPK 설치 방법
- Mi Fitness 연결 및 XMS 권한 설정
- Home Assistant 토큰 발급과 초기 설정
- 엔티티 선택 및 동기화
- 워치 네트워크 테스트
- 자주 발생하는 오류와 해결 방법

## 9. 구현 및 작업 방식

**설계·진단에 그치지 말고 실제 코드를 작성하고 빌드·테스트까지 수행한다.**

기존 TOTP 코드를 먼저 확인하되 검증된 구현은 재사용하고 불필요하게 다시 작성하지 않는다.

전체 구조를 유지하면서 구현에 필요한 세부 기술과 UI는 스스로 판단한다.

단계별로 기능을 구현하고 가능한 자동 테스트를 실행하며 발견된 오류를 수정한다.

실제 기기에서만 검증 가능한 항목과 코드상 검증된 항목은 구분한다.

사용자 확인이 반드시 필요한 경우를 제외하고 중간 승인이나 반복적인 질의 없이 진행한다.

**출력 최소화:** 불필요한 분석 과정, 장문의 계획, 반복적인 진행 보고를 출력하지 않는다. 작업을 우선 진행하고 최종 결과는 변경사항, 빌드·테스트 결과, 실기기 검증 필요 항목만 간결하게 정리한다.

### 최종 목표

1. Android 앱에서 Home Assistant 연결 정보를 설정한다.
2. Android 앱에서 사용할 엔티티를 선택·정렬한다.
3. 해당 설정을 기존 TOTP와 같은 XMS 방식으로 워치에 동기화한다.
4. 워치는 설정을 저장하고 Home Assistant API에 직접 연결한다.
5. Android 관리앱을 종료해도 워치에서 상태 조회와 기기 제어가 가능하다.
6. 사용자는 이후 설정 변경이 필요할 때만 Android 관리앱을 실행한다.

이 아키텍처를 최우선으로 구현한다.
