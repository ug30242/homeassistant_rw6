# 검증 범위 및 실기기 인수 테스트

v0.1.2 사전 릴리즈. 클라우드에서 Mi Fitness 서비스·Bluetooth·중국판 펌웨어를 실행할 수 없으므로 아래 표를 구분합니다.

## 자동 검증

- JavaScript 20개 테스트: 스키마·URL·토큰 제한, UTF-8/Base64/CRC32, 48 KiB/부분 수신/중복/변조/만료, 버전·삭제 반영, 이중 슬롯과 저장·인덱스 실패, 양쪽 자격 증명 삭제, 1006·이전 페이지 콜백, fetch GET/POST/Bearer·오류·타임아웃·취소, 도메인별 명령·실제 상태 확인. 상태 캐시 재사용·TTL·설정 변경 격리, 최대 2개 병렬 조회·취소, 오류 시 과거 상태 보존, 늦은 응답과 제어 결과 충돌 방지.
- Android 26개 테스트: 구성/암호화/인증 태그, hello 준비 전 정보 비전송, 분할·요청 매칭·같은 ID 재시도·취소·시간 초과, 실제 AIDL Parcel 경로와 등록 순서·슬롯 1 ACK·역방향 응답·재연결, 한국어 관리 화면 탭·수명주기, HTTP 인증·리디렉션·타임아웃, Java 생산자 패킷 출력. 2 MiB 초과/2,656개 응답의 스트리밍 파싱, gzip·잘못된 JSON·크기/개수 제한, 도메인 접기·펼치기·50개 페이지·전체 검색과 선택 상태 유지. 즐겨찾기 직접 변경·저장·화면/앱 재진입 및 저장 실패 시 체크 상태 복원 (UI 테스트의 vault는 double 사용).
- Java → 워치 상호운용: Android `SyncSession`이 생성한 실제 다중 청크를 워치 수신 모듈이 소비하여 한국어 설정·토큰을 저장하고 commit ACK를 반환하는 것을 확인.
- `aiot-toolkit` 2.0.5로 실제 RPK 생성. 실제 컴파일된 4개 화면의 첫 프레임·목록·터치 바인딩·직접 fetch·제어·GET/POST 진단·XMS 수신·저장·삭제·화면 종료 타이머 정리를 native double로 실행.
- 최신 빌드의 컴파일된 메인화면에서 캐시 재진입, 조회 중 제어 및 늦은 응답 무시, 실패 시 STALE 표시, 상세화면과 상태 캐시 공유, TTL과 관계없는 주기 갱신, 조회 중 필터 변경 후 새 항목 조회를 실행. 기존 릴리즈 바이너리에는 이 변경이 포함되지 않음.
- Android release APK 생성과 `lintRelease` 오류 0개. APK v2/v3 및 RPK 외부·내부 서명/파일 digest, 같은 공개 인증서·패키지·버전, 백그라운드 서비스 부재를 확인.

native double이 HTTP 응답과 저장 API를 흉내 내므로 실제 TLS 신뢰·Authorization 전달·플래시 내구성·화면 렌더링·터치 정확성은 증명하지 않습니다.

## 직접 통신 실패 시 진단

1. fetch 자체가 없는지, 외부 HTTPS만 막히는지, 특정 HA 호스트·TLS만 실패하는지 분리합니다.
2. Mi Fitness 연결·동반 앱 권한·네트워크 경로를 확인합니다. DNS, 인증서 체인, 서버 방화벽, 로컬 주소 접근 여부를 점검합니다.
3. 서버 요청 로그에는 토큰이 아닌 경로·HTTP 상태·시각만 기록하여 GET과 POST를 구분합니다. 유효/무효 토큰으로 헤더 전달을 간접 검증합니다.
4. 펌웨어 제한으로 확정되면 현 아키텍처의 직접 제어는 지원 불가로 기록합니다. 공인 HTTPS 엔드포인트/지원 펌웨어·Mi Fitness 조합이 대안이며 Android 상주 중계를 몰래 추가하지 않습니다.
